# Profit Control

Profit Control ежедневно получает данные магазина Wildberries, приводит их к единой товарной и денежной модели, рассчитывает экономику магазина и товаров, сохраняет историю карточек и конкурентов и публикует кабинет владельца с проверяемыми рекомендациями.

## Текущая рабочая версия

- Главный источник данных: Wildberries.
- Рабочая схема базы: `client_demo` (задается переменной `SCHEMA`).
- База: PostgreSQL 16.
- Ежедневный процесс: `scripts/run_profit_control_canonical_runtime_v1.py`.
- Расчет рекомендаций: `src/services/recommendation_engine_v2.py`.
- Сбор клиентского снимка: `scripts/build_profit_control_analytics_canonical_runner_v1.py`.
- Кабинет: Next.js в каталоге `cabinet`.
- Основные страницы: `/economics`, `/products`, `/products/{product_key}`.

## Запуск

1. Скопировать `.env.example` в локальный `.env` и заполнить доступы. Не добавлять `.env` в Git.
2. Запустить Docker Desktop.
3. В корне проекта выполнить `docker compose --env-file .env -f docker/docker-compose.yml up -d --build`.
4. Для кабинета выполнить `cd cabinet`, затем `npm install` и `npm run dev`.
5. Открыть `http://localhost:3000/economics`.

PostgreSQL публикуется только на локальном компьютере. Runtime запускается после проверки готовности базы.

Контейнер `profit_control_runtime` выполняет цикл, ждет заданный промежуток и запускается снова. Перезапуск контейнера включен политикой `unless-stopped`. Docker должен быть запущен на компьютере.

## Основные правила проекта

- Денежные выводы строятся только по согласованному снимку данных.
- Основное сравнение — последний завершенный календарный месяц против предыдущего завершенного месяца.
- Текущий месяц показывается отдельно как предварительный сопоставимый период.
- Семь дней используются как раннее направление, один день — только как предупреждение относительно медианы сопоставимых дней недели.
- Движок выбирает одну главную рекомендацию, указывает факты, действие, срок проверки, критерий успеха и следующий шаг.
- При недостатке данных рекомендация блокируется; система не придумывает причину.
- Текущий снимок карточек хранится отдельно от накопительной ежедневной истории.
- Файлы кабинета публикуются после пересчета исходных и итоговых таблиц.
