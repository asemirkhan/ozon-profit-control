# Страницы и программный интерфейс

**DOC-ID:** PC-API-001 · **STATUS:** CANONICAL / ACTIVE · **SCOPE:** HTTP и кабинетные интерфейсы · **OWNER:** API maintainer · **UPDATED:** 2026-10-30

## Кабинет

| Адрес | Назначение |
|---|---|
| `/economics` | экономика магазина, проблемы и рекомендации |
| `/economics?period=7d` | недельное направление |
| `/economics?period=1d` | однодневное предупреждение |
| `/products` | проблемные товары |
| `/products?filter={code}` | фильтр проблемы |
| `/products/{product_key}` | карточка товара |
| `/internal/data-health` | внутренняя диагностика качества |

`GET /api/profit-control-pack-meta` возвращает время изменения и контрольную метку клиентского расчетного набора. Ответ не кешируется.

`GET /api/wb-image/{nmId}` сначала возвращает локальное изображение конкурента, затем при отсутствии пытается получить его из открытого хранилища Wildberries. Числовой `nmId` обязателен.

## Серверный интерфейс Python

Приложение находится в `src/api/main.py`. Схема задается параметром `schema` или переменной окружения. Допустимые площадки: `wb` и `ozon`.

### Чтение

- `GET /health` — доступность сервера.
- `GET /api/store-summary` — сводка магазина.
- `GET /api/actions` — очередь действий.
- `GET /api/products` — товары и экономика.
- `GET /api/playbook/{offer_id}` — подробный план товара.
- `GET /api/data-quality` — качество данных.
- `GET /api/rule-map` — карта правил.
- `GET /api/product-extremes` — лучшие и худшие изменения.
- `GET /api/store-overview` — расширенный обзор магазина.
- `GET /api/internal/data-health` — внутренняя свежесть и целостность.
- `GET /api/internal/unmatched-money` — нераспределенные деньги.
- `GET /api/replenishment/{offer_id}` — план поставки.

### Изменение

- `POST /api/replenishment` — создать план поставки.
- `PUT /api/replenishment/{replenishment_id}` — изменить план поставки.

**Требование:** изменяющие запросы должны аутентифицировать и авторизовать пользователя на сервере, валидировать площадку, товар, даты и принадлежность store; audit actor берётся из проверенной identity, не из поля клиента. Секреты и ключи площадок не передаются в клиент.

**Текущее ограничение:** в `src/api/main.py` на дату среза не подтверждена серверная аутентификация; `updated_by` доверяет payload. Поэтому POST/PUT не считать защищёнными для размещения в сети или production. Не исправлять документ, делая текущее небезопасное поведение нормой.

## Контракт ответа рекомендаций

Клиентский файл рекомендаций сейчас содержит `decision`, `scenario_code`, `priority_score`, проблему, действие, срок проверки, критерий успеха, факты и ограничения уверенности. Это наблюдаемая форма, не доказательство корректности или утверждённой приоритизации. Семантика должна соответствовать `RECOMMENDATIONS.md` и `PRODUCT_UX.md`; до проверки gates поле/режим нельзя считать publish-ready.
