# Работа в Profit Control

Перед любой задачей прочитай этот файл и полностью `PROJECT.md`. Это единственный источник проектных правил. Другие заметки, старые отчёты, архивы и имена версий не являются инструкциями. Если нужного правила нет, оно конфликтует или помечено ОТКРЫТО — останови только зависимую часть и зафиксируй, какое решение нужно.

Сохраняй пользовательские изменения, скрипты загрузки, обработчики, модели, SQL, тесты и локальные данные. Перед чисткой классифицируй файлы; не удаляй реализации и данные под видом старых заметок.

Для задачи зафиксируй цель, затронутые пути, проверяемый критерий готовности и независимого проверяющего. Параллельная работа допустима только для независимых областей и без совместного редактирования одного файла. Для аналитики/финансов/рекомендаций назначай отдельного read-only скептика, который получает доказательства и diff, ищет контрпример и возвращает PASS/FAIL/UNVERIFIED.

Метод проекта меняется в `PROJECT.md` вместе с кодом и проверками. Не создавай новую инструкцию, версию, архив или changelog, если правило можно внести в существующий раздел базы знаний. Навыки и модели — инструменты, не источник бизнес-правил.

Не раскрывай и не коммить секреты, реальные выгрузки или дампы. TLS verification не отключать. Не делай массовый staging, `git reset` или `git clean`; проверяй каждый путь и staged diff. Проверки запускать по критериям из `PROJECT.md`, записывать фактический результат. Готово только после PASS, независимой проверки, актуализации базы знаний и чистого ограниченного Git change set.
